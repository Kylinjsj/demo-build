GitHub Pages 部署 Demo

这个页面由 GitHub Pages 托管。 没有 Node、没有构建命令、没有 Cloudflare Functions， 就是仓库根目录下一个普通的 index.html，被 GitHub 原样发出来。

这是怎么部署上去的

  1. 把 index.html 推送到 main 分支
  2. 打开仓库的 Settings → Pages
  3. Source 选 Deploy from a branch
  4. Branch 选 main，目录选 / (root)
  5. 点 Save，等 1 分钟左右
  6. 顶部出现 https://用户名.github.io/demo-build/

之后每次 git push，GitHub 都会自动重新发布一遍，不用再点任何按钮。

目录可以放哪

Deploy from a branch 模式下，GitHub 只允许两个位置：

  • / —— 仓库根目录（这次用的就是这个）
  • /docs —— 根目录下名为 docs 的文件夹

除此之外的名字，比如 public、dist、build， 在分支部署模式下选不了。 想让构建产物放别的目录，就得改用 GitHub Actions 来发布。

和 Cloudflare Pages 的区别

GitHub Pages    = 纯静态文件托管
                  不能写后端接口，不能读环境变量
                  push → 自动发布

Cloudflare Pages = 静态文件 + functions/ 里的后端
                  能读 context.env.XXX，能连 KV / D1
                  push → 自动发布

之前在 cf_demo 里写的 /api/site、/api/counter 这些接口，在 GitHub Pages 上是跑不起来的，因为那边只有静态文件服务器。
